Start with the story. Read the guild messages, then visit CivicLens to compare the evidence. Every step explains what to do. You can ask for a hint whenever you need one.

What you are doing: Testing a made-up company's website on your own computer. You will make a request, see the response and describe what it means. All people, messages and organisations here are fictional.

Your boundary: Stay inside this training site. The analyst account is meant to see two records. Use the supplied story clues only. You do not need a terminal, developer tools or cybersecurity experience.

Two roles: First you investigate as an analyst. Later you become a training responder, with an access code from Codex. Codex handles the code repair; you check whether the protection really works.

Checking message feed state…
What this is called technically · optional
The integration forwards events to a collector, which stores incoming messages. Revoking the integration disables its credential so that new events are rejected.

              
B
Ask Codex to apply the permission repair
Tell Codex you are ready for the blue team repair. Codex changes the server code, which decides which accounts may open each record. You do not need to edit code.
The repair has to happen in the real server. This page cannot apply it.

              
C
Run the real protection checks
After the repair, check both record access and the data connection. A success message is only meaningful if the tests pass.
